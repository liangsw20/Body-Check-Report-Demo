# 微循 · 全身微循环患者结果解读原型

面向体检中心平板 / 大屏的患者端结果解读原型。核心目标不是展示所有检测数据，而是让受检者在 3 分钟内看懂：

1. 身体哪个部位需要关注；
2. 这个结果在生活里意味着什么；
3. 接下来可以做什么。

> 本项目为产品原型，使用演示数据，不构成疾病诊断，也不能替代医生意见。

---

## 快速预览

### 方式一：单文件打开（推荐分享）

双击打开：

```text
微循原型.html
```

或构建目录中的版本：

```text
dist/微循原型.html
```

CSS、JavaScript 已全部内联到一个 HTML 文件里，不需要后端、不需要安装、不需要联网，发给任何人都能直接打开。

如果需要多文件版本，也可以打开 `dist/index.html`，它会加载同目录下的 `assets/app.js` 和 `assets/styles.css`。

### 方式二：本地服务器

```bash
npm install
npm run dev
```

打开 `http://127.0.0.1:4173`。

其他命令：

```bash
npm run build      # 重新构建 dist，并生成单文件版
npm run single     # 只重新生成 dist/微循原型.html
npm run preview    # 预览已构建的 dist
npm run typecheck  # TypeScript 类型检查
```

### 交付物

- `微循原型.html`：根目录单文件版，直接双击或发给别人；
- `dist/微循原型.html`：构建目录中的单文件版；
- `dist/index.html`：多文件构建版，适合部署到静态托管；
- `患者报告示例.pdf`：由页面打印样式生成的两页患者版报告样例；
- `screenshots/`：桌面、平板、手机、报告和部位详情的最终截图。

## 变成公网网址

项目是纯静态站点，没有后端依赖，可以部署到任意静态托管。

### 最省事：Netlify Drop

1. 打开 [app.netlify.com/drop](https://app.netlify.com/drop)；
2. 把 `dist` 文件夹整个拖进去；
3. 等待几十秒，得到一个 `https://xxx.netlify.app` 网址；
4. 任何人点开就能使用，也可以后续绑定自定义域名。

### 其他选择

- **Vercel**：导入 Git 仓库，自动构建和发布；
- **Cloudflare Pages**：上传 `dist`，国内访问通常更稳定；
- **GitHub Pages**：把 `dist` 发布到 Pages；
- **医院内网**：把 `dist` 放到 Nginx / IIS 的静态目录，仅内网访问。

> 公网演示只能使用演示数据，不要上传真实患者信息。正式上线需要增加登录、脱敏、审计与隐私合规。

## 页面与交互

- **结果首页**：整体结论、四色状态条、全身风险地图、关键指标卡。
- **全身风险地图**：脑供氧、足部末梢循环、血液状态、心脏与血管四个可点击区域。
- **部位解读弹层**：一句话结论、可视化图、原因解释、代表什么 / 不代表什么、下一步建议。
- **详细数据**：默认收起，点击“查看详细数据”展开原始指标、参考范围与状态。
- **行动建议**：今天 / 3 个月内 / 每天三层清单，可点击打卡。
- **患者版报告**：两页 A4 报告，含风险地图、四部位解释、关键数据、行动清单、问医生的问题、复查建议、医生签名和免责声明；支持浏览器打印 / 保存 PDF。

常用交互：

- 点击身体部位卡片或热区 → 打开对应解读；
- 弹层内“上一处 / 下一处”连续浏览；
- 切换演示病例 → 全套图表、文案、报告同步更新；
- “我的报告” → A4 报告预览；
- 报告内“打印 / 保存 PDF” → 调用浏览器打印；
- 页面滚动时，顶部章节导航自动高亮。

## 指标与呈现方式

| 检测模块 | 医学指标 | 患者端表达 | 可视化 |
|---|---|---|---|
| 足趾缺血再灌注 | 恢复时间、峰值充血倍数、阻断后最低血流、左右足差异 | 脚趾血流恢复速度 | 静息—阻断—松开三阶段曲线，标注恢复点 |
| 脑氧监测 | 左 / 右脑氧饱和度、左右差异、脑氧储备 | 大脑左右供氧是否均衡 | 左右脑双区域图、数值与差异 |
| 微流控血液分析 | 总胆固醇、甘油三酯、LDL-C、HDL-C、空腹血糖、HbA1c、全血黏度、红细胞压积、hs-CRP | 血液偏稠、血脂血糖需关注 | 微流控芯片示意、血液流动动画、参考区间条、详细数据表 |
| 中心血流动力学 | 收缩压 / 舒张压、脉压、平均动脉压、心率、HRV、cf-PWV、ABI、SpO₂ | 血压偏高、血管弹性下降 | 连续血压波形、血压刻度、心率 / HRV / 血管弹性小卡 |

### 原型的演示性分级逻辑

以下逻辑只是为了演示“良好 / 需关注 / 建议进一步评估”三种表达，**不是临床验证算法**：

- 足部：恢复时间 ≤ 90 秒且峰值倍数 ≥ 1.8 → 良好；恢复时间 > 150 秒或峰值 < 1.3 → 建议进一步评估；其余 → 需关注。
- 脑部：最低一侧 ≥ 60% 且左右差 ≤ 4 个百分点 → 良好；最低 < 55% 或左右差 > 7 → 建议进一步评估；其余 → 需关注。
- 血液：LDL-C ≥ 4.5、空腹血糖 ≥ 7.0 或血液黏度 ≥ 6.4 → 建议进一步评估；存在其他偏离 → 需关注。
- 心血管：血压 ≥ 140/90 或 cf-PWV ≥ 12 → 建议进一步评估；血压 ≥ 130/85 或 cf-PWV ≥ 9.5 → 需关注。
- 整体：4 个部位均良好 → 状态良好；出现 2 个及以上“建议进一步评估” → 建议进一步评估；其余有异常 → 需要关注。

正式产品需要由临床专家确定指标定义、参考区间、分级阈值和风险模型。

## 技术实现

- React 18 + TypeScript
- 手写 SVG：人体图、血管、足部曲线、脑氧双侧图、血压波形
- 原生 CSS：设计变量、响应式、打印样式
- Rollup + Babel：静态构建，产出可直接打开的 `dist/index.html`
- 无后端、无外部字体、无网络请求

主要目录：

```text
src/
  App.tsx          患者端主页面与上下文
  BodyMap.tsx      全身风险地图
  DetailSheet.tsx  部位解读弹层
  Report.tsx       两页患者版报告
  Visuals.tsx      足部 / 脑部 / 血液 / 血压可视化
  data.ts          三个演示病例与演示性分级逻辑
  charts.ts        曲线与波形生成
  styles.css       设计系统与打印样式
dist/              可直接打开的构建产物
build.mjs          Rollup 构建脚本
serve.mjs          本地静态服务器
```

## 设计与医学边界

- 姓名使用“张先生 / 李女士”等脱敏称呼，不显示身份证等敏感信息。
- 页面明确标注“演示数据”“由医生审核”“最终以医生意见为准”。
- 不以单一分数给患者贴标签，而用“部位数量 + 红黄绿状态 + 行动建议”表达。
- 所有结论都配合“这代表什么 / 不代表什么”，避免把风险提示误解为疾病诊断。
- 报告注明：如有胸痛、胸闷、头晕、单侧肢体无力或言语不清，请及时就医。

### 正式落地前需要补齐

1. 与真实设备 / LIS / 体检系统对接；
2. 由临床专家确认指标参考区间与风险模型；
3. 权限、脱敏、审计、知情同意与数据留存策略；
4. 大屏会话超时、自动清屏与下一位患者复位；
5. 真实报告模板、医院品牌与医生电子签名；
6. 面向老年患者的可用性测试与无障碍验收。
